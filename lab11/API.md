# Конспект TVmaze API

| Питання | Що каже документація | Що показав запит (адреса) |
| :--- | :--- | :--- |
| **Ендпоїнт пошуку за назвою, параметри** | `GET /search/shows?q=:query` | Працює. `https://api.tvmaze.com/search/shows?q=girls` |
| **Форма відповіді пошуку** | Масив об'єктів. Кожен об'єкт містить `score` та `show`. | Повертає масив із 10 елементів. |
| **Ендпоїнт серіалу; як отримати епізоди й акторів одним запитом** | `GET /shows/:id` з параметром `embed`. Допускається масив embed-ів. | `https://api.tvmaze.com/shows/82?embed[]=episodes&embed[]=cast` (повертає об'єкт серіалу з полем `_embedded`). |
| **Поля серіалу, що можуть бути `null`** | `network`, `webChannel`, `dvdCountry`, `image` (якщо обкладинки немає). | Підтверджено на маловідомих серіалах. |
| **Що повертає пошук без результатів** | Статус `200 OK`, порожній масив `[]`. | `https://api.tvmaze.com/search/shows?q=asdfghjkl` -> `200 OK`, `[]`. |
| **Що повертає неіснуючий id** | Статус `404 Not Found`. | `https://api.tvmaze.com/shows/999999999` -> `404 Not Found`, `{"name":"Not Found","message":"","status":404}`. |
| **Ліміт запитів і що робити на 429** | Дозволяє щонайменше 20 запитів за 10 секунд з однієї IP-адреси. При 429 рекомендується почекати. | При перевищенні ліміту API повертає статус `429 Too Many Requests`. |
| **Кешування: що кешує TVmaze і що — браузер** | TVmaze кешує стандартні ендпоїнти. Браузер керує кешем на основі HTTP-заголовків. | Заголовок `Cache-Control: public, max-age=3600`[cite: 7]. Повторні запити віддаються з `(disk cache)`. |
| **CORS: що обіцяє документація і що показав експеримент 12** | Документація каже: "All endpoints are CORS enabled". | Запити успішні, але додавання нестандартних заголовків у GET (як `Content-Type: application/json`) ламає CORS через preflight[cite: 2]. |
| **Ліцензія й атрибуція** | Дані надаються за ліцензією CC BY-SA 4.0. Необхідно вказувати посилання на TVmaze. | Відповідне посилання має бути збережене у футері застосунку. |
